# Epic 2 Context: 预约与并发

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

本 Epic 让一次预约成为不可分割的占位动作：学生选中同一设备连续 1–8 个 30 分钟 slot 后，系统要么完整写入这张预约及其全部占用记录，要么因任一冲突或校验失败而一行不写。它解决的核心问题不是“先到先得”的排队，而是两个请求同一瞬间争同一个 slot 时，由数据库唯一约束而非应用层判断决定谁成功，从而消除双预约。该 Epic 覆盖预约提交、冲突原子拒绝、我的预约与取消，并交付后续管理员改单与锁定共用的 slot 规则内核；成功标准是同 key 并发提交恰好一次成功、占用行数始终不超过 1。

## Stories

- Story 2.1: 提交连续 slot 预约
- Story 2.2: 冲突整单原子拒绝与并发裁决
- Story 2.3: 我的预约与取消
- Story 2.4: 连续多 slot 选择与改单边界

## Requirements & Constraints

- 一次预约只能属于一个设备，包含连续 1–8 个 30 分钟 slot；slot 边界对齐 :00/:30，必须落在设备开放时间内。
- 每个 slot 的开始时刻必须在未来 7 天窗口内，首格不得早于当前时刻；窗口与截止均按瞬时比较，不按本地日期字符串比较。
- 请求必须一次提交整组 slot；任一形状、范围或冲突校验失败时，预约与占用记录均写入 0 行。
- 任一 slot 已被预约或锁定即整单拒绝；响应须列出全部冲突 slot 的 equipment_id 与 slot_start，不能只报第一个。
- 同一学生重复提交同一组 slot 的第二次请求必须冲突失败，不得静默覆盖或合并。
- 学生只能查看和取消自己的预约；取消须在首个 slot 开始前至少 2 小时，取消后全部占用立即释放，重复取消或取消他人预约均为失败且原记录不变。
- 所有写路由要求已登录并携带有效 CSRF token：未登录 401，缺 token 400；页面成功写入后 303 重定向。
- 预约 id 为 `uuid4().hex`；时间戳由应用传参，不使用数据库默认时间；无 JSON 接口、无前端框架。
- 并发正确性：同一 (equipment_id, slot_start) 在两个独立连接或进程同时提交时，恰好一个成功、一个 409、无 5xx，库中该 key 的占用行数恒为 1；不得以 SQLITE_BUSY 作为通过结果。

## Technical Decisions

- 冲突裁决者是数据库：occupancy 上的命名 UNIQUE(equipment_id, slot_start) 约束，列序固定且为普通唯一索引；锁定行与学生预约行共用同一键空间。
- 事务由用例层开启：每个写用例使用统一的 write_tx()，执行 BEGIN IMMEDIATE；仓储函数不 BEGIN、COMMIT 或 ROLLBACK。
- 写入使用裸 INSERT 或 executemany，禁止 INSERT OR IGNORE、OR REPLACE、ON CONFLICT DO NOTHING；唯一冲突须以 IntegrityError 在语句处抛出并被整单回滚。
- 409 的冲突列表在回滚后重新查询，避免把本事务的脏写计入响应；预检查询只用于文案，不作为正确性依据。
- slot 是从设备开放时间派生的量，不建 slot 表；occupancy 是“哪些 slot 被占”的唯一事实源，booking 不冗余存 slot 范围。
- 取消即删除 booking 行，由外键级联删除其 occupancy；已取消预约只通过 audit_log 追溯，不做软删除。
- 审计与业务变更同事务提交；每次预约创建、取消都写日志，不允许写完后异步补日志。
- 所有时刻存为定长 UTC 文本 YYYY-MM-DDTHH:MM:SSZ；同一时刻只有一种字符串写法，保证文本唯一性等价于时刻唯一性。本地时间只在输入解释与页面展示两端转换，且转换只经统一时间工具。
- 形状规则（对齐、连续、1–8 个、开放时间内、7 天窗口、2 小时截止）只在 slot_rules 中实现一次，以 create/edit 两种模式区分场景，管理员不豁免；Web 层只负责把表单字符串转成域对象。
- 状态码集中映射：校验失败 400、未登录 401、无权限 403、冲突 409；成功写入后返回 303 重定向，刷新不重复提交。
- 每个请求使用独立数据库连接，开启外键、WAL 与有限 busy_timeout；连接不得模块级复用。
- 入口为 POST /bookings；我的预约读取 /bookings/mine；取消为 POST /bookings/<id>/cancel，并校验归属。

## UX & Interaction Patterns

- slot 选择是原生多选复选框，字段名 slot，值为 UTC 定长时刻；服务端用 getlist 取回集合。表单只提交一个 equipment_id，跨设备在结构上无法表达。
- 客户端不承担连续性、数量、窗口等正确性判断；禁用 JavaScript 仍可完成预约。
- 成功后 303 跳转结果页；冲突时返回 409 并重渲染同一页面，保留已选 slot 并标出冲突项，避免用户丢失上下文。
- slot 状态由服务端统一计算，模板只渲染状态，不在模板里做时间比较；我的预约列表展示设备、slot 集合、状态与取消入口。
- 取消入口只在允许窗口内可用；越界或已失效时以明确错误反馈，不静默隐藏结果。

## Cross-Story Dependencies

- 2.1 依赖 Epic 1 的设备与开放时间（1.2）以及逐 slot 占用视图（1.3），预约提交复用其 slot 集合与状态语义。
- 2.2 建立在 2.1 的创建路径之上，验证同一写入路径在并发与部分冲突下的原子性。
- 2.3 复用 2.1 建立的 booking、occupancy 与审计写入模式，取消是该模型的删除路径。
- 2.4 在 2.1 的规则基础上补齐 create/edit 双模式边界；其规则内核供后续管理员改单（3.2）使用。
- 本 Epic 产生的预约与取消审计记录，是后续管理员周视图与操作日志（3.1、3.4）的数据来源；唯一约束与共用写入路径也是管理员锁定（3.3）的前提。
