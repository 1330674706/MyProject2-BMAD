## 11. 对架构的最小修改清单

1. **§5.1 D4**：增加 `UNIQUE user.student_no → 409`；保留“其他 `IntegrityError` → 400”但明确 occupancy 之外如何按约束名分流。
2. **§5.1 D2**：把 `claim_slots()` 的事务所有权拆出来，允许调用方用同一 `BEGIN IMMEDIATE` 包住“删旧＋插新＋UPDATE booking＋审计”；禁止嵌套事务。
3. **§5.1 D5**：补三行算法：
   - FR-2 开放时间更新：校验新窗口格式/对齐/顺序 → 查该设备全部 occupancy 的本地 time-of-day → 越界则 `Conflict` 409 回滚 → 更新 equipment → 审计。
   - FR-6 取消：`cancel_booking(conn, booking_id, actor_id, now)` → owner/角色校验 → 2h 校验 → 删除 occupancy → 0 行返回 4xx → 审计。
   - FR-7 改单：校验新 slot 连续/≤8/2h/开放时间/7 天 → 删旧 occupancy → claim 新 → `UPDATE booking`（不改 id）→ 审计 → 提交；失败整体回滚。
4. **§5.6（新增）**：给 FR-2 开放时间变更一个独立小节，写清“越界即 409、原配置不变、不做自动迁移”，并回指 PRD §9.8。
5. **§7.1**：把 slot 表单值改成能携带 `equipment_id` 的复合值，或在服务端增加“每个 slot 必须属于提交的 equipment”的显式校验。
6. **§10**：补齐 `AUDIT_LOG.before_json/after_json`；给 `EQUIPMENT.open_start/open_end` 加 `HH:MM` 格式、`:00/:30` 对齐、`open_start < open_end` 的 CHECK；明确 `open_start`/`open_end` 是本地墙钟规则，不按 ADR-005 转 UTC。
7. **§10.1（新增）**：CSV 契约：`utf-8-sig`；表头固定为 `设备,slot 开始,slot 结束,学号,booking_id,状态`；只导 `kind='booking'` 且 `slot_start` 在自然周半开区间内的行；slot 结束＝开始＋30 分钟；时间按 Asia/Shanghai 展示；状态值固定。
8. **§10.2（新增）**：`audit_log` 字段与 `action` 枚举；`before_json/after_json` 只允许领域字段，禁止 `password_hash`、`password`、`LAB_DEFAULT_PASSWORD`、会话 token；定义 `redact()`。
9. **§11**：增对象级授权规则（学生只能操作 `owner_id=当前用户` 的 booking；管理员可操作全部）；增“日志/导出字段白名单”约定。
10. **§13/§15**：补 `src/serve.py`；启动时创建 `data/` 配置目录；写清单条启动命令与必需环境变量；补 seed 设备 CSV 的列名/幂等/失败行为与 seed 管理员“只建 1 个”的约束。
11. **§14**：把上述落点补进 FR-1/2/4/6/7/8、NFR-2/4 的“受什么约束”列；NFR-4 增加 `app/audit.py`、`app/export_service.py`。
12. **§18**：把“1 周基线记录”“管理员注销误注册账号是否首版支持”“默认开放时间”列为待确认；若不做，写明手工兜底。

**总体判断**：ADR-001（并发唯一约束）与 §5.4（反假阳性证明）是本架构最强的部分，已经完整接住 FR-5/NFR-1 与 D-001；ADR-002/003/004/005 也基本接住部署、渲染、会话与时区。真正没接住的是“跨多个写路径的业务规则”：开放时间变更、取消归属、改单事务、CSV/审计输出契约。这四处不补，Story 2.x/3.x 会各自发明自己的校验与事务边界。
